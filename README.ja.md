# Inkacre

**自分のコンピューターに保存されるページ・ブロック・データベース。AIエージェントと一緒に使える作業スペースです。**

[English](README.md) · [한국어](README.ko.md) · 日本語 · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md)

![はじめにページ](docs/screenshots/page.png)

Inkacre は、おなじみのブロックとデータベースのスタイルでつくった一人用のローカル作業スペースです。内容はすべて手元の SQLite ファイル1つに保存され、
アカウントもクラウドも利用状況の送信もありません。Web 画面、AI エージェント用の MCP サーバー、コマンドエンジンが同じ
ファイルを使うので、エージェントもあなたと同じページを編集します。自分の変更もエージェントの変更もすべて記録され、
元に戻せます。

## よくあるノートアプリにはないもの

- **タイムマシン** — 過去の任意の時点のワークスペース全体を別タブで読み取り専用で開き、ページを今に戻したり、コピーとして取り出したりできます。
- **添付ファイルの内容を検索** — 添付した PDF、Word、Excel、PowerPoint、ハングル（HWPX）、OpenDocument、テキストファイルの中の語でも見つかり、そのファイルと該当行を表示します。
- **リンクマップ** — すべてのページを点に、リンク・メンション・リレーションを線にして表示します。1 つのページを中心に開けば、そのページがつながる先だけを見られます。
- **どこからでもクイックメモ** — アプリを開かずに、ショートカット、Raycast、スクリプト、ターミナルから 1 行、ToDo、データベースの項目を追加します。受信フォルダーに入れたファイルも同じページに入ります。
- **自動バックアップ** — 変更があれば 1 時間ごと・毎日・毎週バックアップし、別のディスクにも置けます。どのバックアップも点検したり、新しいワークスペースとして開いたりできます。
- **Markdown フォルダーミラー** — ワークスペース全体を Markdown と CSV ファイルとしてフォルダーに書き出し続け、Obsidian、エディター、Spotlight、git で使えます。変更の数秒後に反映される一方向のミラーです。
- **エージェントも同じ流儀で** — Claude、Codex などの MCP クライアントは画面と同じ型付きコマンドを使い、その変更も自分の変更と同じく記録され、元に戻せます。

## ノートアプリに期待する機能はそのまま

- **書く** — 入れ子のブロック、/ メニュー、Markdown ショートカット、メンションとリマインダー、バックリンク、コメント、
  ページ履歴、すぐに使える51個のテンプレート。
- **整理する** — 23種類のプロパティ、リレーション・ロールアップ・数式を備えたデータベース。フィルター・並べ替え・
  グループ、テーブル・ボード・リスト・ギャラリー・カレンダー・タイムライン・フィード・グラフ・地図・フォーム・
  ダッシュボードのビュー。
- **データは自分のもの** — バックアップと新しいフォルダーへの復元。Markdown、テキスト、HTML、Word（.docx）、CSV、
  TSV、Excel（.xlsx・.xls）、OpenDocument（.ods）、EPUB、OPML、PDF、5 GB までの ZIP アーカイブ（ほかのノートアプリのエクスポートを含む）のインポート。Markdown・CSV、HTML、PDF（サブページはページごとの PDF）、欠落のない JSON バンドルへの
  エクスポート。
- **複数のワークスペース** — 個人のメモと勉強のように分けたいものを、同じコンピューター上の別々のワークスペースに置いて
  切り替えられます。データはワークスペースごとに別々に保存されます。
- **9言語** — English、한국어、日本語、简体中文、繁體中文、Español、Français、Deutsch、Português (Brasil)。

## つくった理由

- **仕事と切り離した個人の作業スペース。** 個人のメモやプロジェクトを会社のアカウントと混ぜません。アカウントの切り替えや
  ログアウトは不要で、一人で使う機能のために有料プランに入る必要もありません。
- **AIエージェントのために。** Claude などのエージェントが MCP でドキュメントを読み、整理し、更新できます。すべての変更は
  記録され、元に戻せます。
- **クラウドアカウントなしで使えます。** Inkacre はワークスペースをお使いのコンピューターに保存します。場所検索やブックマークの
  プレビューなどの任意機能は、利用時に外部サービスに接続します。接続した AI クライアントには、それぞれのデータポリシーが適用されます。

## クイックスタート

### アプリをパッケージ化する

このフォルダーで `node scripts/package.mjs` を実行すると、このコンピューター用のパッケージが `dist/` に作成されます。実行に必要な Node.js も含まれます。

| システム | ファイル | そのあと |
| --- | --- | --- |
| macOS（Apple シリコン） | `Inkacre-…-macos-arm64.dmg` | 開いて **Inkacre** をアプリケーションフォルダーにドラッグし、そこから開きます。 |
| Windows（x64） | `Inkacre-…-windows-x64.zip` | 展開して `Inkacre` フォルダーの **Inkacre.exe** を開きます。 |
| Linux（x64） | `Inkacre-…-linux-x64.tar.gz` | 展開して `inkacre` フォルダーで `./inkacre` を実行します。 |

Inkacre を開くとバックグラウンドで動き出し、ブラウザーで **http://127.0.0.1:4141** が開きます。動いている間にもう一度
開くと、ブラウザーが開くだけです。終了するには、ワークスペースメニュー（左下のワークスペース名）のいちばん下にある
**Inkacre を終了** を選びます。ワークスペースはシステムのアプリデータフォルダーに保存されるので（[データ](#データ)）、
新しいバージョンはアプリを入れ替えるだけでそのまま使えます。

まだ Apple・Microsoft の開発者証明書で署名していないため、初めて開くときは一度だけ許可が必要です。

- **macOS** では起動が止められます。**システム設定 › プライバシーとセキュリティ** で、Inkacre についての表示の横にある
  **このまま開く** を選びます。
- **Windows** で「Windows によって PC が保護されました」と表示されたら、**詳細情報 › 実行** を選びます。

Intel Mac では、下のようにソースから実行してください。

### ソースから実行

[Node.js](https://nodejs.org) 22.16 以上が必要です（24 推奨）。

```sh
npm ci
npm start
```

**http://127.0.0.1:4141** が開きます。初回はようこそ画面で言語を選び、ガイドとサンプルで始めるか、空のワーク
スペースで始めるかを決めます。

![ようこそ画面](docs/screenshots/welcome.png)

どこからでもコマンドとして使うには、フォルダーからグローバルにインストールします。

```sh
npm install -g .
inkacre            # npm start と同じ
inkacre --help
```

| オプション | 内容 |
| --- | --- |
| `--port <番号>` | 使うポート（既定 4141、または `LOCAL_WORKSPACE_PORT`） |
| `--data <フォルダー>` | ワークスペースの保存先（または `LOCAL_WORKSPACE_DATA`） |
| `--lang <コード>` | 初回画面で選んでおく言語: `en`, `ko`, `ja`, `zh-CN`, `zh-TW`, `es`, `fr`, `de`, `pt-BR` |
| `--no-open` | ブラウザーを開かない |

起動中にもう一度起動すると、起動中のアプリを開くだけです。

### Docker

```sh
docker build -t inkacre .
docker run -d --name inkacre -p 127.0.0.1:4141:4141 -v pageyard-data:/data inkacre
```

ポートは必ず `127.0.0.1` だけに公開してください。[セキュリティ](#セキュリティ)を参照。

### アップデート

ソースから実行している場合は、新しいバージョンのフォルダーで `npm ci` を実行します。

そのあとアプリを再起動します。画面は `web/app/` にビルド済みなので、ビルドは不要です。

## データ

| システム | 既定のフォルダー |
| --- | --- |
| macOS | `~/Library/Application Support/Pageyard` |
| Windows | `%APPDATA%\Pageyard` |
| Linux | `$XDG_DATA_HOME/pageyard`（通常 `~/.local/share/pageyard`） |

以前のバージョンの `data-live/` や `data/` フォルダーがリポジトリ内にあれば、そのまま使い続けます（`data-live/` を優先）。フォルダーには `workspace.sqlite` と
`blobs/`（添付ファイル）があり、新しく作ったほかのワークスペースはその中の `workspaces/<id>/` に保存されます。バックアップは左下の **?** メニューの **バックアップを作成** から作り、復元は新しい
フォルダーに行います。

```sh
inkacre restore --from /バックアップ/フォルダー --to /新しい/フォルダー
inkacre --data /新しい/フォルダー
```

復元は既存のフォルダーを上書きせず、先にハッシュ・整合性・リビジョンを確認します。

バックアップは自動でも作られます。既定では 1 日 1 回、変更があったときだけです。**設定 › バックアップ** で間隔、自動バックアップを何個残すか、保存先を決めます。同じディスク上のバックアップはディスクと一緒に失われるので、別のディスクのフォルダーを選んでください。そこにあるバックアップは丸ごと点検したり、今のワークスペースの横に新しいワークスペースとして開いたりできます。

同じフォルダーの `file-text.sqlite` には検索用に添付ファイルから読み取ったテキストが入り（削除しても読み直します）、`backup.json`・`inbox.json`・`mirror.json` にはこのコンピューターで使うバックアップ、受信フォルダー、Markdown ミラーの設定が入ります。

## クイックメモ

**設定 › クイックメモ** でページを選べば（またはページを指定すれば）、このコンピューターのどこからでも追加できます。

```sh
inkacre capture --todo "牛乳を買う"                     # クイックメモのページに ToDo として
inkacre capture --to "日記" "今日の思いつき"             # タイトルで指定したページに
inkacre capture --db "読書" --prop "著者=夏目漱石" "こころ"   # データベースに項目を追加
pbpaste | inkacre capture --to "受信メモ"                # 標準入力、1 行につき 1 ブロック
```

リクエストを送れるツールなら何でも使えます。`http://127.0.0.1:4141/api/capture` に `{"text": "…", "as": "todo"}`
のような JSON を POST してください。Apple のショートカットなら **URL の内容を取得** アクションひとつです。設定画面に
そのままコピーできる例があります。記録は通常の変更と同じで、**変更履歴** に残り、元に戻せます。

**受信フォルダー。** 同じ設定画面でフォルダーを選ぶと、そこに新しく入ったファイル（スキャン、スクリーンショット、ダウンロード）が数秒後にクイックメモのページに追加され、ほかの添付と同じく内容検索できます。既にあったファイルは取り込まず、何も削除しません（取り込んだファイルを横の `Imported` フォルダーに移すこともできます）。

## AI エージェント（MCP）

アプリを起動したまま、エージェントに MCP サーバーを追加します。

```json
{
  "mcpServers": {
    "inkacre": { "command": "inkacre", "args": ["mcp"] }
  }
}
```

グローバルにインストールせずリポジトリから実行している場合は、command に `app-local` のフルパスを書きます
（[mcp.example.json](mcp.example.json)）。Claude Code なら1行で追加できます。

```sh
claude mcp add inkacre -- inkacre mcp
```

アプリを別のポートで実行しているときは、MCP サーバーに `LOCAL_WORKSPACE_URL`（既定 `http://127.0.0.1:4141`）を指定します。

| 用途 | ツール |
| --- | --- |
| 読み取り | `workspace_status`, `workspace_get`, `workspace_query`, `workspace_search`, `workspace_tasks`, `workspace_command_schema`, `workspace_history`, `workspace_page_version` |
| ワークスペース | `workspace_list`, `workspace_use` |
| プレビュー・交換 | `workspace_preview_property_conversion`, `workspace_import_preview`, `workspace_export` |
| 変更・復旧 | `workspace_apply`, `workspace_capture`, `workspace_undo`, `workspace_attachment_put`, `workspace_backup` |
| 実行メモ | `workspace_run_log`, `workspace_run_list`, `workspace_run_read` |

`workspace_apply` には一意のコマンド ID、エージェントが読んだリビジョン、操作の一覧が必要です。1つのまとまりは全部
保存されるか全部取り消され、同じコマンドを再送すると最初の結果が返り、古いリビジョンは新しい作業を上書きせずに拒否
されます。エージェントの変更も自分の変更と同じく **変更履歴** に表示されます。

## セキュリティ

Inkacre にはログイン機能がありません。`127.0.0.1` だけで待ち受け、ローカルのホスト名で届いた、自分の画面から
のリクエストだけに応じるため、ほかのコンピューターやほかのサイトからはアクセスできません。ネットワークのアドレスや
公開プロキシの後ろには置かないでください。インターネットを使う機能（地図タイルと場所検索、ブックマークのプレビュー、
オートメーションの Webhook・メール）は、使ったり設定したりしたときだけ動きます。PDF ファイルは、このコンピューターに
ある Chrome・Edge などの Chromium 系ブラウザーが作成します。空のプロファイルでバックグラウンドで起動し、ネットワークには
出ません。そのようなブラウザーがない場合、PDF のエクスポートは印刷画面を開きます。

添付ファイルはこのコンピューター上のバックグラウンドスレッドで検索用に読み取られ、どこにも送られません。Markdown
ミラーは選んだフォルダー（最初は空）にだけ書き込み、そこで変更されたファイルを上書きしたり削除したりしません。

バックアップ、受信フォルダー、Markdown ミラーは選んだフォルダーだけを使い、ミラーと受信フォルダーは Inkacre のデータフォルダーを受け付けません。

## どう作られているか

- **ファイル 1 つ、履歴 1 つ。** 現在のオブジェクトと、それを変えたすべてのコマンド（変更前と変更後）が 1 つの SQLite ファイルにあります。元に戻す、ページ・データベースの履歴、タイムマシンはすべてこの履歴から生まれ、バックアップはこの履歴を丸ごと含みます。
- **変更の道は 1 つ。** 画面、MCP サーバー、コマンドラインは同じ型付きコマンドを送ります。スキーマで検査した操作を、基にしたリビジョンに対して 1 つのトランザクションで適用します。まとめて保存されるか一切保存されないかのどちらかで、同じコマンドの再送には最初の結果を返し、古いリビジョンは拒否します。
- **素の Node.js。** 1 つのプロセス（Node 組み込みの SQLite、ネイティブモジュールなし）が 127.0.0.1 で画面を提供し、バックグラウンドの仕事もこなします。添付ファイルの読み取りは worker スレッドで、バックアップ・ミラー・受信フォルダーは同じプロセスで動きます。
- **このプロジェクトのために書いた部分。** エディターは React と ProseMirror です。PDF のテキスト読み取り（CJK フォントと標準暗号化を含む）、Office・HWPX・OpenDocument の読み取り、.xls の取り込み、ZIP64 のストリーミング取り込み、リンクマップのレイアウトは、パーサーを持ち込まずにここで書いています。
- **実際のブラウザーで検証。** エンジンとサーバーのテスト（`npm test`、プッシュごとに CI で実行）と、人が使うように画面を操作する `scripts/ux-trace/` の Playwright スイートがあります。

## 開発

```sh
npm install
cd ui && npm install && npm run build && cd ..   # 画面を web/app/ に再ビルド
npm test                                         # エンジンのテスト
node scripts/package.mjs                         # このシステム用のダウンロードを dist/ に
```

画面は `ui/` の React・TypeScript・ProseMirror、エンジン・サーバー・MCP サーバーは `src/` の Node です。ブラウザーでの
確認は `scripts/ux-trace/`（`local-suite*.mjs`）にあり、`node scripts/handoff-ui-fixture.mjs` で作った隔離データに対して
Playwright で実行します。
